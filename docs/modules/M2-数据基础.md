# M2 — 数据基础

## 状态

**Next**

## 合并范围

本阶段合并原 M2 ArtifactStore 与原 M3 SQLite 与迁移。

## 目标

建立 Standalone 模式的受控文件存储和权威元数据基础：ArtifactStore 负责 artifact ID、哈希、原子写入、资源归属、软删除与回收边界；SQLite Repository 负责领域元数据、事务、版本和安全导入旧数据。

## 前置依赖

- M1 契约与领域模型已完成。
- 复用 `packages/contracts` 的 Artifact、owner、status、revision、错误和资源引用语义。

## 允许修改范围

- ArtifactStore 模块、Repository/SQLite、迁移工具、对应 adapter 与数据层测试。
- 本文件及 `CHANGELOG.md` 的当前阶段记录。

## 不在本阶段

- Python 算法和评测；Electron/Vue 页面；Spring Boot、LAN、CI、打包。
- 旧项目写入、真实患者数据、未授权数据集、模型权重或凭据。

## 交付与验收

- artifact 内容不通过绝对路径跨层传递；写入具备哈希校验、原子提交、归属校验和受控删除。
- SQLite schema、迁移、回退和旧数据导入报告可重复；禁止全量快照缺失即删除。
- 使用合成 fixture 覆盖重复导入、归属错误、损坏文件、迁移失败和回滚。
- 通过契约测试、ArtifactStore/Repository 测试和 M0 基线验证。

## 交接给 M3

交付稳定的 artifact ID、元数据事务、版本引用和数据保护边界；下一阶段不得绕过 Repository 读写数据库或绕过 ArtifactStore 读写文件。
